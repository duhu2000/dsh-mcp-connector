# 0.2.45 市场截图顺序建议

## 当前差距

当前 `screenshots.json` 声明的 4 张素材均来自 `v0.2.37`，画面标题也显示 `v0.2.37`：

1. 市场总览。
2. 连接器详情与 Prompt。
3. 单个连接器详情内的旧“工具详情”。
4. `mcpServers` JSON 导入。

它们可以证明市场浏览、连接器详情和 JSON 导入，但不能证明 0.2.45 的以下新增能力：

- 独立“工具”页和跨连接统一搜索。
- 连接/服务/发现状态筛选及分页。
- 来源、最近发现状态与最后成功缓存时间。
- 易读参数、枚举/约束/嵌套结构。
- 单连接诊断、“重新发现工具”和“检查连接”。

因此，当前截图不应继续作为 0.2.45 宣传验收的完成证据。

## 推荐展示顺序

市场支持 1–8 张截图。建议在新的 0.2.45 素材通过搜索闭环验收后，按以下顺序组合：

| 顺序 | 画面 | 必须可见的证据 | 用户意图 |
|---:|---|---|---|
| 1 | 统一工具搜索结果 | 顶部版本 `v0.2.45`、独立“工具”页、真实搜索词、跨连接结果、来源、最后成功缓存时间 | 我能否快速找到工具 |
| 2 | 筛选与参数详情 | 连接/服务/发现状态筛选；参数类型、必填、枚举或约束、可展开嵌套结构 | 我能否判断工具怎么用 |
| 3 | 连接状态与排障 | 单连接诊断建议、“重新发现工具”“检查连接”、失败或陈旧缓存的诚实状态 | 出问题后能否定位和恢复 |
| 4 | 市场总览 | 超百个连接器目录、分类与搜索；不得出现真实凭据或把目录数写成用户数 | 我能接入哪些服务 |
| 5 | JSON/手动接入 | `mcpServers` JSON、stdio/HTTP 与本机凭据提示 | 我能否迁入已有配置 |
| 6（可选） | 多 Server 连接器详情 | 一个连接器对应多个 Server、授权边界和工具入口 | 复杂连接如何管理 |

若首轮只提供三张新素材，优先顺序固定为“统一工具搜索 → 参数详情 → 连接诊断与重新发现”；旧市场总览和 JSON 导入可排在其后，而不是占据前三位。

## 素材验收规则

- 使用 1280×720 外层视口与 800px 产品面板，避免与真实宿主布局不一致。
- 必须显示 `v0.2.45`，不能沿用 `v0.2.37` 标识。
- 模拟数据必须显著标注“演示数据”或“无凭据 Mock”；工具名、结果和故障状态不能让读者误认为真实客户数据。
- 不出现 OAuth Token、API Key、Authorization Header、本机真实路径、用户会话、查询结果或其他敏感内容。
- 缓存画面必须同时保留状态语义，不能让“最后成功缓存”看起来像当前服务健康或可调用。
- 参数详情用于展示结构，不点击或执行目标工具。
- 排障画面可触发无凭据 harness 的模拟状态，不更改真实 web profile。
- 更新图片后重算 `assets.json` 的哈希与尺寸，并通过 `npm run storefront:check`；由总账会话统一修改公共 `screenshots.json`。

## 分发说明

awesome-dsh-plugin 从插件仓库根目录的 `screenshots.json` 读取 1–8 张相对路径，并在夜间构建采集；截图顺序由该文件控制。更新产品仓库截图后通常不需要再向 awesome-dsh-plugin 提交截图 PR。描述 YAML 更新与截图更新是两个独立动作，应分别验收。
