> 目标：对标 WorkBuddy（腾讯）/ TraeWork（字节）/ QwenWork（阿里）三家连接器市场，打造「DSH 最好用的 MCP 连接器插件」。
> 基于：三家市场页面截图 OCR 提取（16 张截图，2026-08-23 抓取）。
> 现状：我们当前支持 `oauth2-pkce / bearer / api-key / none` × `streamable-http / sse`，stdio 正在开发中。

## 二、问题 1：是否需要「推荐/热门」分类 + 其他分类？

### 结论：**强烈需要，且我们有现成的数据字段，几乎零成本**

| 需求 | 我们现状 | 需要的改动 |
|------|---------|-----------|
| 推荐/热门 | ❌ 无 | `catalog.json` 已有 `featured: true` 字段，只需 UI 加「推荐」Tab |
| 分类过滤 | ❌ 无（只有搜索） | `catalog.json` 已有 `category` 字段，只需 UI 加分类 Tab |
| 分类 Tab | ❌ 无 | `ui/index.html` 加分类筛选条 |

### 建议的分类体系（综合三家 + 我们「企查查企业数据」定位）

采用 **9 类 + 推荐**（对齐 TraeWork/QwenWork 的 8 类，额外突出「企业数据」核心）：

```
全部 | 推荐 | 企业数据 | 金融投资 | 法律合规 | 开发工具 | 办公协作 | 调研分析 | 设计创意 | 效率工具
```

**为什么单独设「企业数据」分类**：这是企查查的核心强项和品牌锚点，也是三家都没有单列、但用户高频搜索的类别。该分类仅收录企查查生态产品，**不收录竞品**（天眼查、启信慧眼、企百科、水滴征信、同花顺快查等均为竞品，不予收录）。

### 实现要点（低成本）

1. `category` 枚举值标准化为上述 9 类（现有 registry 的 category 值需对齐）
2. `featured: true` 的连接器进「推荐」Tab
3. UI 加分类筛选条（横向滚动 chips 或下拉），复用现有 `listCatalog` 的 `category` 参数（已支持 ✅）

## 四、问题 3：当前技术实现方式可行性评估

### 4.1 三家市场连接器的对接方式分布（从截图判断）

| 对接方式 | 占比（估算） | 典型连接器 | 我们当前支持 |
|---------|:----------:|-----------|:----------:|
| **stdio（CLI/npx/uvx 本地进程）** | **60-70%** | GitHub、飞书、钉钉、企业微信、Notion、Obsidian、Figma、Slack、Vercel、Supabase | ❌ **开发中** |
| **HTTP/SSE（url + headers）** | 20-25% | 企查查、北大法宝、Wind、腾讯地图、高德云图 | ✅ 已支持 |
| **API Key（header）** | 10-15% | Tavily、博查搜索、威科先行、恒生聚源、东方财富 | ✅ 已支持 |
| **OAuth（PKCE/授权码）** | 5-10% | 飞书、Google、Microsoft 365、企查查 | ✅ 已支持 |

### 4.2 逐类可行性结论

| 分类 | 当前可覆盖 | stdio 完成后 | 说明 |
|------|:---------:|:----------:|------|
| 企业数据 | ✅ 90%+ | ✅ 100% | 以 HTTP/API Key/OAuth 为主，几乎全支持 |
| 金融投资 | ✅ 85%+ | ✅ 100% | 以 API Key 为主 |
| 法律合规 | ✅ 90%+ | ✅ 100% | 以 API Key/Bearer 为主 |
| 开发工具 | ⚠️ 30% | ✅ 95% | **大量 stdio**（GitHub/GitLab/Vercel/Supabase） |
| 办公协作 | ⚠️ 40% | ✅ 90% | **大量 CLI**（飞书/钉钉/企业微信/Notion/Obsidian） |
| 项目管理/CRM | ✅ 70% | ✅ 95% | API Key 为主，少量 CLI |
| 调研分析 | ✅ 80% | ✅ 95% | API Key 为主 |
| 设计创意 | ⚠️ 40% | ✅ 90% | Figma/设计工具多 stdio |
| 效率工具 | ✅ 70% | ✅ 90% | API Key + 本地 |

### 4.3 核心结论

> **stdio 是补齐「大厂全覆盖」的决定性缺口。**
> - **当前**：只能覆盖约 **40%** 的三家市场连接器（企业数据/金融/法律类，我们的主场已覆盖 90%+）
> - **stdio 完成后**：可覆盖约 **95%+**，几乎对齐三家全部连接器

**关键判断**：
1. 我们**已在主场（企业数据/金融/法律）做到 90%+ 覆盖**，这是差异化优势
2. **stdio 开发完成后**（已转 GPT），开发工具/办公协作/设计创意三大类从 30-40% 跃升到 90%+
3. **无需自研任何协议**——stdio 走 `dsh-mcp-client` 透传，HTTP/SSE/API Key/OAuth 已支持
