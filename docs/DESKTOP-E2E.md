# Desktop / Web UI 回归清单

## 本地自动检查

在安装了开发依赖的源码目录运行 `npm run check`。通过后运行 `npm run dev:ui`，打开 `http://127.0.0.1:4173/mcp-connector/ui/`。测试页面使用 Mock 目录、连接和工具数据，适合复核搜索、分页、表单错误和键盘操作。

## Desktop 手动检查

在独立测试 profile 中完成以下项目。记录插件与 Host 版本、平台、测试范围和观察结果。涉及 OAuth 回调、宿主重启或本地进程的项目需要在对应宿主中验证。

| 操作 | 预期结果 |
|---|---|
| 重启宿主，切换工作区并重建侧栏 | 连接器入口可用且只出现一次。默认入口位置不可用时，仍可通过备用入口打开面板。 |
| 切换宿主语言和主题，用键盘打开和关闭详情 | 文案和主题跟随配置。Tab 顺序合理，Escape 关闭弹框后焦点回到触发按钮。 |
| 浏览市场、打开已连接卡片、搜索和加载下一页工具 | 卡片详情、连接状态和工具列表与当前选择一致。 |
| 分别使用手动、JSON 和市场入口添加连接 | 错误的输入有修正提示。凭据型市场卡片在服务初始化通过后才进入已安装列表。 |
| 将参数化 Prompt 带入当前工作区 | 可复用空白草稿。有文字或附件的原草稿保留，另建草稿。重复点击只处理一次，用户确认发送前内容留在草稿中。 |
| 使用测试账号完成 OAuth 回调、重启、停用、启用与断开 | 界面状态与实际连接一致。旧插件迁移按用户手册核对工商和法律入口。 |
| 在两个工作区切换分类、搜索和滚动位置 | 各工作区恢复各自的浏览状态。迟到的响应不会覆盖当前页面，授权表单重新打开时不回填上次的敏感内容。 |

旧插件迁移的用户操作见[用户手册](USER-GUIDE.md#企查查旧插件迁移后显示连接异常)。

## stdio 本地参数覆盖

在能够解析 `@deepseek-ai/dsh-mcp-client` 和 `@deepseek-ai/cordis` 的 Host 安装环境中，可用隔离容器运行集成测试。下面的 Bash 命令需要替换示例路径。

```bash
DSH_HOST_INTEGRATION_ANCHOR=/path/to/dsh/package.json node --test test/local-overrides-host.test.mjs
```

Desktop 手动回归时，使用无害的测试服务，检查首次启动失败后的表单保留、修正参数后重试、编辑与清除覆盖、快照恢复，以及停用后重启宿主。Windows 另测含空格的可执行文件路径和工作目录。提交回归结果时注明覆盖的平台，并使用脱敏摘要或 Mock 截图。
