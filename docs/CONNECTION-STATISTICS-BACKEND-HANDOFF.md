# 连接卡片累计统计：企查查后端交接

日期：2026-10-27。部署决策：现有企查查后端，由后端团队部署。
状态：待后端评审的接口提案；尚无生产服务或真实社区统计。Connector 草稿 PR #195 仅含本机基础。

## 口径与责任

主指标为“累计成功连接”，按统计实例与公开卡片去重；副指标为“近30天新增”。成功是连接初始化、工具发现和保存全部完成，不是点击、OAuth 授权或业务调用成功。一个卡片的多个 Server 只计一次。重连、升级、重复回调和断开不改变累计。实例不是独立用户，多 profile、多设备和重装可能造成重复，展示须说明参与范围与统计起点。

后端负责事件入口、公共目录白名单、事务去重、限流、聚合接口、部署和监控；Connector 负责明确参与开关、事件生成、持久化重试队列、超时隔离和卡片展示。前端不能直接提交一个可任意增大的累计值。

历史已配置但未验证的卡片不算成功；已知历史卡片在用户参与后实际验证成功，可进入累计，但不能成为当天新增。不开启追溯上传过去事件。原始本机快照不可直接相加作为社区总量。

## 接口提案（路径待后端确认）

### POST /v1/connection-events

Host 通过 HTTPS 发送单个事件，建议请求体上限 4 KiB，拒绝额外字段：

```json
{
  "schemaVersion": 1,
  "eventId": "随机 UUID，重试不变",
  "instanceId": "独立随机统计标识，不含设备或账号信息",
  "connectorId": "公开目录稳定 ID",
  "eventType": "first_success",
  "occurredAt": "2026-10-27T03:00:00.000Z",
  "pluginVersion": "发布包版本"
}
```

`eventType` 允许 `first_success` 或 `baseline_success`。后者必须同样已完成成功验证，仅排除近30天新增，不上传未验证配置。采用 UTC 时间；服务端保存 receivedAt，限制未来偏差和过旧事件，具体阈值须在联调时固定。客户端最多重试7天，建议接受窗口覆盖该期限；不得把过期事件重写为今日事件。

成功首次写入返回 201；同 payload 重复返回 200，均为 `{ "ok": true, "status": "accepted" }` 或 `duplicate`。相同 eventId 不同 payload 返回 409。400 为字段错误，403 为拒绝接收，422 为非法卡片或时间，429 带 Retry-After，5xx 可退避重试。错误响应不得回显敏感数据。只有明确 accepted/duplicate 才删除本机待发送事件。

事务内同时执行事件幂等与 `(instanceId, connectorId)` 唯一约束。不同 eventId 重复连接不能加数；baseline_success 不能被后来的 first_success 升格成新增。服务端合计按去重记录计算，禁止先加计数后保存去重键。保留去重键的期限必须覆盖累计周期，否则不能宣称长期去重。

### GET /v1/connector-statistics

仅返回公共聚合数据，不公开 instanceId/eventId 或逐人时间线：

```json
{
  "schemaVersion": 1,
  "scope": "participating-instances",
  "startedAt": "2026-10-27T00:00:00.000Z",
  "updatedAt": "2026-10-27T03:05:00.000Z",
  "items": [
    {"connectorId": "公开卡片 ID", "cumulativeSuccessfulConnections": 123,
     "newSuccessfulConnections30d": 12}
  ]
}
```

以上数字和日期仅为协议示例，不能上线为初始统计。未知或隐藏值使用 null，不能填0。近30天以聚合时刻 UTC 滚动窗口计算，只含 first_success。建议5分钟聚合、ETag/缓存；客户端保留更新时间，过期标明或隐藏热度。统计不可用不得阻断连接或恢复为虚假0。纠错、去刷或合法删除可以修正累计，并记录调整原因。

## 数据与运行要求

- 只接收公共卡片白名单；不收集 Token、API Key、OAuth身份、机器序列号、目录路径、私有端点、对话、工具参数和结果。
- 开关默认关闭。关闭后立即停止生成上传事件并清空待发送队列；在途请求可能已送达，不能承诺撤回。已上传记录删除机制需后端给出方案。
- 不复用企查查业务凭据做统计认证；开源包不能包含共享服务端秘密。随机实例标识并非身份认证，需组合限流、异常检测与审核；不得声称绝对防刷。
- 网关日志避免保存请求体，明确 IP 日志、事件、去重键的保留周期及删除方式。保留期未定前，不开启生产采集。
- 客户端异步有界队列、指数退避、超时、退出处理及跨进程锁需在社区上线前实现。队列满或事件过期丢弃并本机诊断，不无限增长。

## 联调验收

- 同一事件并发100次只增加1；不同事件同一卡片同实例仍为1；不同实例可分别计数。
- 相同 eventId 不同 payload 被拒绝；事务中途失败后重试不重复计数。
- baseline_success 进入累计但不进入新增；30天滚动后累计保持，新增自然下降。
- 失败、取消、回滚、未验证历史记录、私有卡片和非法字段不进入统计。
- 网络超时、429、5xx、重启、两个 Host 同时运行均不影响业务连接，并保持队列幂等。
- 参与与退出符合界面说明；默认安装不上传；数据保留与删除可验证。
- 卡片仅显示服务端真实聚合；缺失/过期数据不伪造；搜索相关性与编辑精选不被热度强制覆盖。

这些校验不等于后端完成：事务幂等、防刷、队列、参与开关和真实接口仍需实现。当前 Host 不导入该模块、不生成统计身份、不发网络请求。时间窗口由调用方显式传入，测试的7天/5分钟仅为提议参数，待后端确认。错误信息固定，不回显拒绝的数据。
