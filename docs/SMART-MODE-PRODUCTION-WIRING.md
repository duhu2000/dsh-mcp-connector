## 接线与最少操作

| 路径 | 实现与边界 |
| --- | --- |
| 插件启动 | `lib/index.js` 可选注入 Host 服务；`smart-mode-host.js` 从官方 profile 安装锚点解析运行库，精确核对五个 Host 包版本和 Native 实例。未知版本/能力不乐观启用；旧 Host、CLI、全局 compact 模式保留原行为 |
| 范围识别 | `smart-mode-production.js` 只匹配当前 `config.account`、单个明确 grant、官方 issuer/六个官方 endpoint；缺条目或多完整 grant 不猜测、不拼接账号。首期固定组为 `qcc-enterprise-six-v1` |
| 人工身份 | 调用真实 `connection.admit()`，且只接受当前 `connection.browserPeer` 的未中止 owner 身份。回环/同源、伪造请求头、请求正文及其他真实签名 API peer 均不是此控制页授权。仍使用 CSRF nonce 和严格参数白名单 |
| 原始目录 | 在现有 tools/list 返回与缓存清洗之间捕获原始定义，只保留于内存。使用记录身份和发现代次拒绝迟到结果；注册变更先失效再复用正常元数据发现。停用/删除成员不阻塞其余有效成员发布；不增加业务调用 |
| 权限 | 组合原有连接可用性、Workspace、治理和手动激活控制器；模型发现可见的手动工具不会自动激活，准备/调用仍受其限制。停用智能层不会撤销其他权限层 |
| 会话 | 页面创建/恢复委托真实 `SessionController`；列表使用 Host SessionQuery；工作区沿用 Host 放置语义。首次可信交互输入在推理前选择模式，开启前会话和空会话保持兼容。继承、持久化恢复、清空/压缩复用原模块 |
| 默认与回退 | 兼容启动不挂载智能限制层或改变连接注入设置。一次预览/确认先通过空闲与能力预检，再挂载和写模式；写盘失败撤回新挂载。已保存 smart 默认在重启时恢复，准备状态始终不落盘 |
| 页面 | 原市场页既有能力探测自动显示“智能工具”；新增工作区选择并复用当前工作区消息桥。中英文保持一致；层未挂载时禁用搜索/清空/压缩按钮 |

六个 Server 为 `qcc-company`、`qcc-risk`、`qcc-ipr`、`qcc-operation`、`qcc-history`、`qcc-executive`。法律、法宝、其他账号和其他连接不纳入本期，不改变它们的定义数量，也不承诺整个会话下降 90%。

用户不必设置六条连接的注入模式，不必先另行开启智能层，也不必每次对话点击工具。管理员仍须提前完成独立只读/来源核验；本轮没有把该责任转移给模式确认或模型。完整操作与回退说明见 [用户说明](SESSION-TOOL-INJECTION.md#development-preview-english)。

临时“停用智能层”只影响当前进程；重启仍依照保存的默认模式。持续兼容回退需要先确认“新会话使用兼容模式”，再停用智能层。运行中的 Agent、未完成准备或在途调用不能被不安全地卸载。

## 已验证的真实 Host 契约

精确验证版本为 `0.2.2-rc.1`，包括 AgentLoop、ToolRuntime、NativeToolExecutor、Connection 和 SessionController。使用其真实 Cordis 服务、Native schema/lookup/dispatch、签名 Cookie、会话控制器、JSONL 持久化、SessionQuery 精确读取与原生压缩命令。SessionQuery 夹具使用 `openAt: never`，不把这次运行当作 SQLite 索引或原生二进制部署验收。

所有服务运行在单独临时 profile。连接器 KV/Loader、OAuth grant、Workspace 清单、附件及离线模型适配器使用合成夹具；现有 profile 的安装锚点仅用于解析代码。没有加载现有 DSH 配置、会话或凭据，没有通过实际 `dsh` 命令安装到生产。因此这是“正常插件启动路径 + 真实 Host 服务”的隔离契约验收，发行安装和真实账号端到端仍待验收。

`SessionController.prompt` 在这个版本自行构造 `kind:user`、rpcId 和非 owner principal；生产适配器依赖这个明确契约区分交互输入，单独 `kind:user` 不构成证明。该假设不把同进程插件视作不可信隔离沙箱，未知 Host 版本不自动沿用。

## 回归结果

Node `22.22.1`，显式设置安装模块锚点和独立证据目录后执行 `npm run check`：**1040 项测试，1035 通过、0 失败、0 取消、5 项原有跳过**。相对 PR #243 新增 15 项，无新增跳过。lint、中英文检查、文档/元数据、教程链接和打包门禁通过；发布文件 143 个，仅新增两个运行库模块，测试夹具和工程报告不进入 npm 包。

新增覆盖包括：

- 正常 `apply()` 默认不启用；一次确认；旧/新会话隔离；完整原始定义在清洗前可核验。
- 真实签名浏览器 owner、签名 API peer 拒绝、伪造身份与跨源拒绝；多个 Workspace 的必选/放置与成员关系。
- 真实磁盘写失败后的挂载回滚和重试；忙碌旧会话阻止初次启用且不写默认模式。
- 原有手动模式仍需激活、Workspace 隔离、治理拒绝、成员停用后其余来源仍可用、回滚不移除外部 deny。
- 仅合成、完整指纹绑定的只读记录下 prepare 成功；另一会话不可见；定义变化后旧核验失效；停用/重挂和全新 Host 上的 JSONL 冷恢复均不恢复加载状态。
- 多账号/多 grant、缺失或非官方 endpoint 拒绝；缺少 profile 和未知安装版本拒绝；不支持的执行器新会话保持兼容，已建立 smart 快照不自动扩大为兼容。

全量运行产生 62 份 Host/profile 回执，覆盖 59 个不同临时 profile，均已清理。全量中既有成功/失败/取消回归共执行 4 次纯本地合成业务函数；新增生产接线测试的业务函数执行为 0。真实业务和真实模型请求均为 0。五项原有跳过不包含本轮完整 Host 契约。

内置浏览器在临时 Host 上观察到：正常市场页显示入口；初始兼容且层停用；创建会话保留工作区选择；一次预览确认启用；层停用与兼容默认回退；英文页面及工作区预选正常。截图保存在本轮独立产物目录。驻留助手首轮因标准输入关闭而超时；已改为明确停止文件，关闭/清理复测通过，Host 错误为 0。

本轮当前 DSH 的 `cordis.yml`、`cordis.patch.yml`、`package.json`、`pnpm-lock.yaml` 开始/结束 SHA-256 相同。该检查只覆盖这四个配置文件，不将其扩大为后台所有运行存储不变的声明。真实只读批准、真实等价来源批准和生产智能模式启用均为 0。

## 距离用户实际可用的剩余工作

1. **真实只读核验与受信审核接入。** 将目标工具完整原始定义指纹与独立核验证据、有效期和撤回机制绑定。当前正常入口不信任人工自填哈希或 `readOnlyHint`，启用审核默认拒绝；还需确定可信审核证据的生产交付/校验方式，再对首批真实工具验收。未完成前，相应真实工具 prepare 会拒绝。
2. **真实重复来源核验。** 对需要合并的候选核对返回语义、计费、限流、新鲜度及逐组开关，形成版本化关系。未批准关系保持独立入口，不影响已经核验的独立来源按需路径；不要求为了发布而批准全部 170 个候选。
3. **经单独授权的真实端到端与收益 A/B。** 独立 profile 上验证首批只读 canary，再测 v4-pro/flash 实际请求、usage、缓存与成本。当前全量测试是离线适配器；1500/5000 组内预算和估算结果不是实际 provider 收益，也不是整个会话成本承诺。
4. **交付与灰度。** 将本分支变更纳入维护者审阅并对齐届时主线、完成最终 CI 和安装/升级/重启回退验收，再另行批准合并、发布和少量账号启用。保留默认兼容和逐组停用。

本轮不推进上述真实批准、模型/业务调用、生产安装和发布操作。下一项应先明确可信只读审核证据的生产交付，再安排有限真实验收；不能只打开开关就宣称客户问题已完整解决。
