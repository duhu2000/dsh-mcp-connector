# 数据 MCP 贡献与验收模板

新增数据连接器时，请在 Registry 提交描述符，并写清楚使用者能访问哪些数据、需要什么授权，以及哪些能力已经验证。目录结构、描述符格式和 PR 流程见[连接器上架指南](https://github.com/duhu2000/dsh-mcp-connector-registry/blob/main/docs/ONBOARDING.md)。

## 提交材料

| 项目 | 请填写 |
|---|---|
| 名称与用途 | 连接器名称、提供方、适用地区、数据范围和典型用途 |
| 官方来源 | 可核对归属的厂商页面、官方仓库或 Registry 条目，以及公开的包名或服务端点 |
| 使用条件 | 鉴权方式、费用或额度、代码许可证、数据许可和服务条款链接 |
| 版本与维护 | 测试版本、最近更新时间及维护状态 |
| 重复关系 | 与已上架连接器的稳定标识、端点或上游数据是否重合，以及功能差异 |
| 验证范围 | 验证日期、连接结果、已验证工具和能力、仍需用户自行验证的限制 |

## 验收标准

1. **连接与工具发现。** 分别记录 `initialize` 和 `tools/list` 的结果。说明权限要求、工具可能产生的副作用及其判断依据。只读注解可以作为线索，业务验收还需要实际调用结果。
2. **业务数据。** 在授权和费用允许的范围内，选一个有代表性的只读工具，用最小必要参数完成一次调用。核对返回字段、来源、时间范围、单位及缺失值的含义，并说明结论适用的范围。
3. **人工审核。** 维护者核对来源、条款、重复关系和验收摘要，记录审核日期和获准公开的能力范围。如果维护者仅批准连接验证范围（`connection-only`），卡片标记为 `partial`，业务运行状态保留为 `not-run`。

## 可公开的验收摘要

公开材料只填写版本、日期、验证范围、结果和必要的脱敏字段说明。凭据、客户或个人数据、原始业务响应和本机路径均应从正文、日志和截图中移除。

以下为合成示例，可按实际验收范围填写。

| 项目 | 示例 |
|---|---|
| 工具与调用范围 | `get_monthly_total`，单月汇总，只读 |
| 核对字段 | `month`、`total`、`unit`、`source` |
| 核对结果 | 月份与请求一致，单位与服务文档一致，来源字段有值 |
| 验证限制 | 已验证单月返回。跨月汇总和空值处理待验证 |
