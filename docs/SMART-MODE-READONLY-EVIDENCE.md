# QMCP-4963 · 可信只读核验证据的生产交付与校验

## 本轮结论

在独立分支 `codex/qmcp-4963-readonly-evidence` 完成代码和合成回归，基于生产接入提交 `a3e5c21`。正常插件启动现在会消费管理员预置公钥所认可的离线签名证据包，自动向 prepare 提供只读核验结果；历史本地记录、人工填写哈希、工具前缀和 MCP 只读提示均不能独立取得生产核验权限。

仍只覆盖当前配置账号、单个明确 grant 的企查查企业数据六个 Server。默认兼容、旧会话、Workspace、治理、手动激活、Host 审批、来源选择及预算/TTL 语义保留。真实只读定义和来源关系批准均为零；不因代码支持签名证据而宣称真实定义已经只读。

## 交付协议与可信边界

完整字段、签名字节和交付步骤已纳入随包发布的 [使用说明](SESSION-TOOL-INJECTION.md#可信只读证据交付尚未发布)。

- 管理员通过外部可信渠道核对独立审核方 Ed25519 SPKI 公钥，在目标 profile 的 `smart-mode-evidence/trust.json` 预置范围、profileBinding、公钥状态与有效期。插件不生成签名私钥、不安装信任根、不从 URL 下载，也不提供模型/网页签发或导入接口。
- 审核方交付 `bundle.json`：独立签名的 v1 完整快照，绑定当前账号、服务组、目标 profile、单调 revision、时间窗，以及每项 sourceId、完整原始定义指纹、独立证据摘要和审核方摘要。签名采用域分隔的规范化 JSON；公共 `readOnlyEvidenceSigningBytes(payload)` 供外部签发环境复用，不提供签发能力。
- 一个包最多 1 MiB / 1024 项，公钥文件最多 32 KiB / 16 项；严格拒绝未知字段、额外业务样本/schema、重复项、不正确范围、非公钥、未知/撤回/到期密钥和错误签名。包不批准来源等价关系。
- 有效只读记录直接供 prepare 使用，不要求用户逐工具操作。人工本地撤回仍优先；人工重新启用也必须有当前独立签名证据，不可延长证据有效期或换用自报哈希。
- 包为完整快照：更高版本遗漏或禁用某项即撤回。删除包、移除/停用公钥、到期、损坏都拒绝后续准备/调用。公钥轮换保留 profileBinding，并发布更高版本的新签名包。

签名证明签发者和完整性，不能证明业务事实上只读。管理员预置信任公钥与审核方持有私钥属于不同职责；模型、网页或 tool 参数不能建立新的信任根。插件与同进程代码、能改写整个 profile 的管理员之间不构成文件系统隔离沙箱。

## 代码接线

| 位置 | 变化 |
| --- | --- |
| `lib/read-only-evidence.js` | 固定本地交付路径、严格数据模型、Ed25519 校验、范围/期限约束、接收版本下限、原子磁盘接收记录、失效监控与稳定错误状态 |
| `lib/smart-mode-production.js` | 在真实 Host 启动组合中创建校验器；连接 prepare、人工审核、状态和 inspect；层停用/恢复复用信任边界，插件卸载关闭监控 |
| `lib/smart-mode-integration.js` | 生产专用的同步核验过滤器；未设置时保留显式受控工厂原契约；已准备项也复核当前证据 |
| `lib/smart-mode-restrictions.js` | 派发发现失效并拒绝时同步刷新 restriction，使 schema/lookup 同时收窄 |
| `lib/smart-mode-control.js`、`ui/smart-mode.*` | 只展示可信证据状态和当前定义核验；自动填充撤回所需证据摘要；不增加信任根安装、签发或上传 API；中英文同步 |
| `lib/index.js`、`package.json` | 公共校验/规范化辅助 API、lint 和既有打包白名单；不增加 DSH 设置或修改配置文件 |

版本下限写在独立 smart domain 的 `evidence_receipts/`，原子硬链接发布且不覆盖，记录仅包含范围、profileBinding、revision、内容摘要与校验和。每次使用重新核对签名、时限和持久下限，拒绝低版本与同版本不同内容；并发写者发布后复读，不能把较旧视图作为当前授权。写盘失败没有内存批准回退，修复后可重试。

已签名、范围正确的过期/未来包也会推进版本下限，随后保持不可用；恢复要发布更高版本，不能重新放回旧批准包。版本下限基于仍完整的本地接收记录，不覆盖人为回退整个 profile/信任根的场景。存储沿用本地原子硬链接要求；Windows 整机断电耐久性未作承诺。

推理组装和执行派发边界同步复核。文件监控及 1 秒元数据轮询兜底收窄空闲 lookup 视图，避免 OS 通知丢失后长期残留；不是等待重启才失效。直接读取 Host 原始 schema/lookup 的静态视图可能先于文件通知，不能将其当作业务调用授权。派发即使先于通知也会拒绝，并刷新该视图；已入站在途调用不追溯取消。

## 真实核验还要做什么

1. 由业务和安全责任人指定真实独立审核方，明确公钥保管、分发、轮换、撤回和 profileBinding；本轮没有为真实账号建立信任根。
2. 对首批拟支持的真实来源，重新核对原始 tools/list 完整定义和当前来源绑定，独立确认参数、返回语义、是否产生写入或其他副作用。工具名或 readOnlyHint 不可作为结论；定义变化后重审。
3. 在独立审核环境生成真实 dossier，保留证据，签发范围明确、有效期有限的真实只读快照。随后经单独授权，在隔离 profile 预置真实公钥并原子交付证据包，验证首次准备、撤回、重启和密钥轮换。本轮没有生成或批准这样的真实包。
4. 需要合并的重复来源另行核验语义、计费、限流和数据新鲜度，形成来源关系；本模块签名不承担等价批准。
5. 另行批准有限真实只读 canary 与 v4-pro/flash 请求/usage/缓存/成本 A/B，再完成主线对齐、维护者审阅、发行安装/升级/回退验收及灰度。代码完成和离线合成通过不替代真实业务与发布验收。

本轮只提交代码及合成验证，不修改当前 DSH 配置，不调用真实业务或模型，不批准真实只读定义/来源关系，不启用生产智能模式，不合并或发布。
