## 0.2.50：官方授权流程设计

统一入口：检查环境 → 发起官方登录 → 等待用户确认 → 查询授权状态 → 注册工具。
状态：未配置、未授权、授权中、取消、超时、授权失败、已授权但连接失败、已连接。

Host 仅允许固定 Provider 的固定登录命令，禁用任意命令/参数输入。调用入口沿用同源和本机访问限制；同一系统用户同一 Provider 串行授权。
先验证固定 dws 版本是否提供可稳定消费的设备码/授权 URL 输出及取消机制；没有稳定契约则保留终端登录，不解析不稳定的人类文本冒充 API。
设备码仅在当前授权 UI 短暂展示，不写日志、对话或审计；授权 URL 限定官方允许域名；取消/超时终止本次进程且不清除既有有效登录。
凭据继续由官方 CLI 管理。成功后严格复查 authenticated；账号/组织展示须核验官方字段并脱敏，不因拿到工具清单而宣告身份正确。
测试：无浏览器、拒绝授权、过期设备码、网络中断、重复点击、跨 profile、Keychain 不可访问、切换组织、退出登录、重启恢复。真实账号验收单独记录。

## WPS 验证清单

来源：[官方云文档 MCP](https://open.wps.cn/documents/app-integration-dev/mcp-server/tools/mcp_kso-yundoc)。
文档列出读写 scope delegated:kso.mcp_yundoc.readwrite，且工具包含开启分享和权限修改，不能宣传为服务端只读授权。

- [ ] 确认开发者资格、应用审批、可用账号/套餐、OAuth 客户端方式。
- [ ] 核实只读 scope 或替代只读 API；若只有读写 scope，明确披露并获得审批。
- [ ] Host 执行层仅允许搜索、内容、评论、元信息四类读取；拒绝分享和权限修改及未来未知工具，不仅隐藏 UI。
- [ ] 两个权限不同的测试账号验证文档隔离、分页、限流、Token 过期和撤销。
- [ ] 未获得真实租户证据前保留候选状态，不声明可用。
