## 0.2.50：官方授权流程设计

### P1 开工核验（2026-09-15）

- 提示修复 PR #82 已合并；P1 在 feat/dingtalk-auth-flow 独立开发，尚未接入页面或发布。
- 本机固定版 1.0.61 的 `auth login --help` 确认默认 loopback、`--device`、`--no-browser`；不使用 `--recommend`、Token 注入或自定义授权端点。
- [固定版设备码源码](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli/blob/v1.0.61/internal/auth/device_flow.go) 的 dfPrintDeviceCodeBox 直接写入本地化终端文本。服务端 JSON 字段不等于 CLI 暴露的稳定事件协议；暂不抓取终端文本向页面透传。
- 先落地纯状态流转与单元测试：登录退出成功后必须再查状态，取消/超时后忽略晚到结果，不保存输出中的身份和 Token。此组件尚未接入运行期。
- 后续顺序：验证 loopback 进程生命周期与平台启动 → 同源 Host 授权任务接口（不可由模型工具启动）→ 页面发起/取消/检查 → 具备资格账号验收。
- 设备码路径单独核验官方机器可读输出契约；不满足时仅提供终端引导，不承诺页面一键设备码。

### P1 授权任务管理进展

- 已实现可注入 launch/verify 适配器的任务管理器：串行启动、随机任务 ID、取消、最长 5 分钟超时、卸载清理、登录退出后的独立状态核验。
- 取消或超时仅发送 AbortSignal，任务清理完成前禁止重启；适配器必须在 abort 后终止实际进程并结束 Promise。不能以此宣称已验证真实跨平台进程树终止。
- 只返回 phase/attemptId，不缓存身份、Token、设备码、URL 或原始错误；未知错误保留为失败/未知，不推断管理员限制。
- 单元测试覆盖并发启动、取消期间重启、晚到成功、超时和敏感错误。尚未接入 Host 路由/页面，尚未发起真实登录。
- 下一验收门槛：固定 CLI 启动适配器在 macOS/Windows 的进程树取消、网络超时、卸载无残留；同源路由必须拒绝跨站调用，且不暴露为模型工具。

统一入口：检查环境 → 发起官方登录 → 等待用户确认 → 查询授权状态 → 注册工具。
状态：未配置、未授权、授权中、取消、超时、授权失败、已授权但连接失败、已连接。

Host 仅允许固定 Provider 的固定登录命令，禁用任意命令/参数输入。调用入口沿用同源和本机访问限制；同一系统用户同一 Provider 串行授权。
先验证固定 dws 版本是否提供可稳定消费的设备码/授权 URL 输出及取消机制；没有稳定契约则保留终端登录，不解析不稳定的人类文本冒充 API。
设备码仅在当前授权 UI 短暂展示，不写日志、对话或审计；授权 URL 限定官方允许域名；取消/超时终止本次进程且不清除既有有效登录。
凭据继续由官方 CLI 管理。成功后严格复查 authenticated；账号/组织展示须核验官方字段并脱敏，不因拿到工具清单而宣告身份正确。
测试：无浏览器、拒绝授权、过期设备码、网络中断、重复点击、跨 profile、Keychain 不可访问、切换组织、退出登录、重启恢复。真实账号验收单独记录。
