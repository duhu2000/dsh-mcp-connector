## 发现与修复

发现一项需要修复的证据异常恢复问题：回执硬链接已发布、其后持久化确认失败时，后续相同版本会只核对回执存在与摘要就接受证据。新接收器也会跳过未完成的持久化屏障。Linux 上若目录同步失败，该路径无法证明接收的防回放 revision floor 已按既定契约落稳；原包可能在不确定写入错误后过早恢复只读许可。

独立故障注入直接在原 tgz 复现。新增永久回归在修复前有两项失败：同进程重试/新接收器在同步仍失败时应拒绝；确认旧回执期间出现并发的新撤回时应以新 revision 为准。未观察到此次问题造成跨会话可见性或真实业务执行。

`lib/read-only-evidence.js` 现在对当前接收器尚未确认的已有回执同步文件，并在 Linux 等平台同步目录，随后重新核对最新 revision / 摘要；失败继续拒绝，磁盘恢复后可重试。成功确认的同一摘要在当前接收器内缓存，正常 schema / 派发重复读取不新增 fsync。缓存不代替每次签名、期限、信任与持久化最新 head 的复核；重启后重新确认。

本轮只修复该恢复边界并增加验收回归，保留冻结新增功能；没有新增签发、批准、信任安装、来源合并或产品操作入口。
