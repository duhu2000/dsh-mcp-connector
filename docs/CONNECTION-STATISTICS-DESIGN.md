# 连接数量统计：实施记录与社区汇总契约

## P0 已实现（本机，不代表社区上线）

- Host 最终 connect/configure 返回成功后记录，不在按钮或通用存储函数计数。
- 当前 profile + 连接器 ID 去重；同一卡片多 Server、重连、重新授权不重复增加。
- 启动时已有连接记为历史基线，未验证不计成功；以后成功验证可进入累计，但不进入近 30 天新增。
- 断开不删除统计；失败、取消、回滚、自定义 JSON 和动态 URL 连接不计入市场卡片成功量。
- 独立 connection_statistics 表只保存卡片 ID、首次观察时间、首次成功时间、历史标记。不保存账号、凭据、业务参数或调用结果。
- 已安装页“本机连接统计”及同源 API connectionStatistics 可查看累计、近30天新增、历史基线。成功仅表示连接流程完成，不表示业务调用成功。
- 关闭凭据持久化时使用内存记录，UI 明示重启清空；存储错误不改变连接成功结果，统计显示不可用。
- 没有统计上报、客户端身份生成、统计域名、社区数字或热门排序。保持现有市场顺序。

本机累计为成功连接过的不同卡片数量，不是独立用户数。同一 profile 同时由多个 Host 写入时，现有存储域没有新增跨进程事务保证；社区上线前必须增加独立持久化 outbox/锁，不能用这些本机快照直接相加宣称精确总量。插件卸载清理数据或重建 profile 也会丢失本机历史，不能据此反推产品上线以来总量。

## P1 计划：企查查后端服务契约（部署方已确认，未部署）

2026-10-27 用户确认：使用现有企查查后端，由后端团队部署。接口提案与联调清单见 [后端交接文档](CONNECTION-STATISTICS-BACKEND-HANDOFF.md)。这不代表接口已实现或生产地址已配置。

首选单独事件入口与只读聚合接口，不将任意统计域名放进 Registry 描述。客户端开关默认关闭；开启前展示发送字段、用途、保留期限和退出行为。退出停止上传并清空未发送队列；不追溯上传过去成功事件，历史基线独立处理。

提议事件字段：schemaVersion、随机 eventId、去标识化随机统计实例标识、公开 connectorId、eventType（first_success / baseline_success）、发生时间、插件版本。只允许服务器公共目录白名单，不能上传私有描述 ID、端点、用户标识、组织、工具参数和结果。统计实例不是人；多设备/多 profile 的限制应公开说明。

POST /v1/connection-events：HTTPS、限长、严格字段白名单、限流、时间偏差检查；eventId 幂等，首次成功以 (instanceId,connectorId) 唯一约束。服务端应同一事务完成去重与累计更新，重复重试不加数，baseline_success 必须已经验证成功，进入累计但不转成今日新增。随机客户端 ID 不是强反作弊凭据；需异常检测与审核，禁止声称绝对防刷。

GET /v1/connector-statistics：仅聚合数据，包含 schemaVersion、统计起始日期、updatedAt、覆盖说明、卡片 ID、累计成功连接、近30天新增。小样本可隐藏，未知值用 null 而非0。没有事件接收鉴权秘密放入开源客户端。

已实现并接入服务适配层的独立文件 outbox 与参与状态基础（生产部署 null，不启用），含跨进程锁、有限重试和退避，详见后端交接文档；统计请求失败/超时不能阻断连接。默认不启用网关 IP 日志长期保存；部署时明确保留期限和可删除机制。后端团队负责部署资源；生产域名、接口路径和接入策略待双方联调确认。

## P2：公开展示与排名（客户端已实现，生产未启用）

卡片主指标“累计成功连接”，副指标“近30天新增”，附统计起点、参与范围、更新时间。不称用户数、当前在线数、npm下载量。累计正常增长，纠错/去刷允许修正。

新增“累计热门”“近期热门”显式排序，搜索相关性优先。编辑精选与社区热度分开标注。服务端聚合只对已收录公开卡片生效，数据过期或不可用不填造数字，不覆盖精选规则。待有足够样本再评估成功率、趋势和新卡片探索机制。

## 验收

单元覆盖并发去重、持久化恢复、时间窗口、历史基线、失败/回滚、私有参数排除与存储失败隔离。已补可执行契约校验、队列双进程持久化与参与状态单元测试。正式上线仍需真实 Host 连接路径与双 Host 验收、服务端幂等与防刷测试、界面参与/退出与真实断网恢复测试。未完成这些步骤前不得对外宣称社区累计统计上线。
