This is a concrete information-loss fix, not proof that all loops on the reporter's DSH 0.2.2-alpha3 environment are resolved. Real model/Host regression remains required.

The initial sandboxed run could not bind fixture HTTP ports; the successful full run used approved local fixture listeners. No user's DSH was started/stopped. Changes are not yet committed, pushed or released; product-media freshness/real UI and real-provider acceptance remain release follow-ups.

## #208 — upstream response type investigation (not fixed)

The report observes `application/json,application/json; charset=UTF-8` failures in both DSH and an independent MCP client. The plugin's `lib/mcp-http.js` discovers tools; business tool calls are delegated to the Host MCP client. Changing the plugin discovery parser alone cannot establish a fix for business dispatch.

No real provider call or credential access was performed in this change. Obtain only sanitized HTTP status, Content-Type values and request identifiers for initialize, tools/list and tools/call from an authorized test environment. Compare server/gateway output with client input; never attach authorization headers, cookies or full configuration. Fix the responsible layer, rather than broadly accepting arbitrary response types. Require independent-client and DSH call/repeat/error-branch acceptance before closing #208.

## #210 — bounded registration observation

When a supported Host has not registered stdio tools, the first minute is pending rather than terminal failure. A five-second background observation cadence reads Host registration without spawning another process or invoking business tools. It works without an SSE subscriber during the bounded startup period. Success resets normal discovery cadence; a persistent absence returns to ordinary backoff and the actionable startup diagnostic. Unsupported/erroring Host status does not enter fast retries. Existing disabled/stale-record guards remain in place.

An isolated fake-Host regression registers a synthetic tool after the initial pending result, then verifies automatic cache recovery without manual recheck. This does not prove the reported TuShare root cause or real Web/Desktop acceptance. Still test clean first connection, slow package bootstrap, failure/recovery, removal/disable during startup, actual authorized read-only invocation, and manual Host restart on each target platform. Do not close #210 solely on unit tests.
