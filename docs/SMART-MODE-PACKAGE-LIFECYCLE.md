# QMCP-4963 · 安装、升级、重启及降级验收

## 2026-11-16 验收复核与 Windows tar 修订

最新结论、预算口径和回归见 [验收复核报告](SMART-MODE-ACCEPTANCE-2026-11-16.md)。Windows 验收入口改为从 SystemRoot/WINDIR 选择绝对 System32/tar.exe，避免 Git Bash 的 GNU tar 将盘符当成远程主机；不统一添加原生 bsdtar 不支持的 --force-local，也不修改用户 PATH。非 Windows 行为保持原样。6 项永久 tar 回归及 Windows Git Bash 的实际生命周期加入门禁。

本次回归使用 395f46c 的不变 runtime 输入与修订后的验收脚本，lib/ui 运行库未改。预算是离线估算；来源等价批准只影响去重，真实只读核验才是智能 prepare 的必要前提。默认兼容的合并/发布决定不与真实启用批准混为一谈，本轮仍不执行合并或发布。

## 实际路径与隔离

使用 DSH 0.2.2-rc.1 **官方 CLI `plugin --profile ... add <本地 tgz>`** 安装和换版；每次启动均是新的操作系统进程。进程加载官方 `PluginPackages` / `createRuntimeResolution`，从临时 profile 的实际 `node_modules` 找到并导入插件 `apply()` / `Config`，核对版本、路径归属和入口文件摘要。没有以源码导入冒充安装完成，也不依赖同进程 ESM 缓存模拟重启。

首次、升级两个 profile 均位于有 QMCP-4963 标记的独立临时 DSH_HOME。真实 Host 的 Native、SessionController、浏览器身份与 JSONL 保留；OAuth、连接存储/Loader、元数据及模型使用合成夹具。连接、grant、治理等合成 KV 确实写入临时磁盘，在下一进程重新读入；智能快照、签名证据和防回放回执使用插件自身存储路径。不读取日用 DSH 的配置、凭据或会话。

本地安装器/启动进程为 Node 26.13.0、pnpm 10.32.1；CI 固定 Node 24、pnpm 11.1.1 和 Host 0.2.2-rc.1，在 Linux / Windows 运行同一流程。SDK 安装器要求 Node ≥24.9；普通离线契约全仓仍以 Node 22.22.1 验证。

**降级语义：** 稳定版 0.2.109 不实现智能层，其行为是恢复原有注入和权限控制，不能声称仍执行新版本的只读核验、预算或 TTL。普通治理、Workspace 与手动规则仍由旧插件执行。本轮不在降级阶段执行业务调用。智能域保留而不迁移/删除，以便再次升级复核。

## 发现与修订

发现本地提测包的版本标记问题：`0.2.110-pr.243.28e1349` 在实际 `compareVersions()` 中小于 `0.2.110-pr.243.ce02515`。短 Git SHA 不代表版本先后，因此后交付的代码可能被更新流程判断为降级；稳定版 0.2.109 到原 28e1349 包的提升本身正常。

新增仅用于 QA 的版本生成器 `scripts/fixtures/smart-mode-package-version.mjs`：`<下一补丁>-pr.<PR号>.qa.<构建序号>+g<SHA>`。排序由明确的递增构建序号控制，SHA 只保留为 build metadata。本地构建与 CI PR 包统一使用毫秒级构建序号，不修改仓库 release version，不发布 npm 版本。三项永久回归中，两项在旧标记规则下失败、修正后通过，覆盖旧包排序、SHA 逆序/同构建元数据和非法输入；其他 PR 号也保留。

另处理了一处 Windows 回归环境限制：pnpm 的本地路径缓存索引可因长 tarball 路径超过文件名长度。回归先验证原包 SHA-256，再复制到自己临时目录内的短名 tgz，摘要再次一致后交给官方安装器；不修改用户原包、系统配置或 pnpm 源码。

新增测试夹具参数仅供注入已安装模块和跨进程合成 KV，不进入 runtime 包。生产运行库相对 28e1349 没有新增代码变更。

## 永久回归与运行方式

`scripts/check-smart-mode-package-lifecycle.mjs` 默认构建当前源码候选并获取固定的 0.2.109 基线，执行 16 个安装/启动/恢复步骤（另有打包步骤），最后严格验证临时目录归属和标记再删除。每次 Host 启动记录独立 PID。损坏包的非零退出是预期用例，不当作成功安装。

```powershell
$env:DSH_HOST_INTEGRATION_ANCHOR = '<独立安装的完整 Host 0.2.2-rc.1 package.json>'
$env:DSH_SMART_PACKAGE_EVIDENCE_DIR = '<本轮独立回执目录>'
node scripts/check-smart-mode-package-lifecycle.mjs
```

只下载 npm 包依赖，不连接真实业务/模型。已解压提测包而无 Git 历史时，通过 `DSH_SMART_PACKAGE_CANDIDATE` 与必需的 `DSH_SMART_PACKAGE_CANDIDATE_SHA256` 指定随包 tgz；可用 `DSH_SMART_PACKAGE_BASELINE` 指定本地稳定版包，避免重复下载。所有安装、换版和新进程阶段仍实际执行。

修订后本地完整 `npm run check`：**1100 项，1095 通过、0 失败、0 取消、5 项原有跳过**；runtime 144 文件的白名单/安全、lint、文档/元数据与教程门禁通过。普通提测契约为 **362 项、零跳过**，实际安装生命周期是额外门禁，不能用普通契约数量代替。最终包与 CI 按相同 commit 单独核对。

## 本轮边界

本轮证明指定包在官方 CLI 包管理 + 官方模块解析 + 隔离 Host 服务上的安装生命周期；没有启动整套日用 Web/Desktop，也没有验收 Desktop 外壳、dshmarket 等第三方 Update Provider 的完整图形更新流程、任意旧版本、断电耐久性或网络盘。

真实业务/模型调用、真实只读/来源批准、真实公钥部署、生产模式启用、PR 合并及发布均为零。日用 DSH 四项配置前后摘要单独核对。本轮测试的合成公钥、签名、grant、会话和默认模式只存在于可清理临时 profile。真实业务核验、真实信任交付、授权后的限定调用/A-B 及合并/发布/灰度决定仍待后续处理。
