# 分类体系 + 推荐位 —— 设计与实现

> 目标：参考 TraeWork、QwenWork 和 WorkBuddy 的市场信息架构，让用户在“全部”页按章节浏览，也能一键切换到单一分类。
>
> 状态：已实现（v0.2.16，2026-08-24）。

## 一、交互结论

### 1.1 分类导航

- 市场只保留“全部 / 推荐 / 9 个业务分类”，不显示服务商下拉框和接入方式筛选。
- 桌面宽度下 11 个标签保持一行且不出现横向滚动条；窄屏自动换行。
- 分类栏位于固定 Header 的第二行，向下浏览卡片时始终可见，且不会悬浮覆盖正文。
- 市场和已安装总数显示在对应页签内；市场正文不再单独占行提示卡片操作方式。
- 全文搜索继续与“全部”或当前分类组合使用。

### 1.2 “全部”页

“全部”不是一张混合卡片网格，而是按以下固定顺序展示章节：

1. 推荐
2. 企业数据
3. 金融投资
4. 法律合规
5. 开发工具
6. 办公协作
7. 调研分析
8. 设计创意
9. 效率工具
10. 其他

每章默认最多显示 4 张卡片（当前双列布局即两排）。超过 4 张时显示“查看全部 N 个”，在当前章节内展开，展开后可“收起”。没有卡片的章节不渲染。

### 1.3 单分类页

- 点击“推荐”只显示所有 `featured=true` 的卡片。
- 点击任一业务分类，只显示该分类的全部卡片，不再做 4 张预览限制。
- 点击“全部”回到分章节视图。

历史值由 UI 兼容归一化：

| 历史值 | 标准分类 |
|---|---|
| `金融数据` | 金融投资 |
| `法律数据` | 法律合规 |
| `数据采集` | 效率工具 |
| `通用工具` | 其他 |

`category` 在 schema 中继续保持自由字符串，以兼容第三方目录；公共 Registry 的源文件必须直接使用标准分类。

## 三、推荐位规则

推荐位严格保留 6 张卡片，不再采用“所有上架卡片均推荐”或“每类至少推荐 1 张”的策略：

| 顺序 | 连接器 | 业务分类 |
|---:|---|---|
| 1 | `qcc-company`（企查查·企业工商） | 企业数据 |
| 2 | `qcc-legal`（企查查·法律数据） | 法律合规 |
| 3 | `qcc-tender`（企查查·招投标） | 企业数据 |
| 4 | `qcc-document`（企查查·文档报告） | 效率工具 |
| 5 | `pkulaw-legal`（北大法宝·法律检索） | 法律合规 |
| 6 | `wind-stock-data`（Wind·股票数据） | 金融投资 |

独立 Registry 中只有北大法宝和 Wind 保持 `featured=true`；其他第三方卡片均为 `featured=false`。合并目录按连接器 `id` 去重后，推荐章节仍只出现上述 6 张。

## 四、分类运营约束

### 4.1 企查查卡片

- `qcc-company`、`qcc-tender`：企业数据。
- `qcc-legal`：法律合规。
- `qcc-document`：效率工具；依靠精选排序与目录声明顺序排在该章节首位。

### 4.2 企业数据不收录竞品

“企业数据”是企查查核心主场，只收录企查查生态产品。天眼查、启信慧眼、企百科、水滴征信、同花顺快查企业数据、上奇产业通和天创信用星图等竞品不进入公共市场目录。用户自行通过 URL 或 JSON 导入的本机连接不受影响。

### 4.3 设计创意

首张设计创意卡片为 `seedream-image-generation`：

- 服务商明确标为 **Ace Data Cloud**，不标注为 ByteDance 官方 MCP。
- Hosted MCP：`https://seedream.mcp.acedata.cloud/mcp`。
- Bearer Token 仅保存于 DSH 本机，Registry 不携带任何凭据。
- 图片生成可能计费，精选 Prompt 要求先确认模型、尺寸和计费条件再执行。
- 公网无凭据探针应能建立 MCP 请求并得到 HTTP 401 鉴权挑战；完整工具调用需要用户自己的有效 Token。

## 六、验收标准

1. 桌面分类标签一行完整显示，无横向滚动条；窄屏自然换行。
2. 市场卡片向下滚动时，分类栏固定可见，且不与卡片或章节标题重叠。
3. 默认“全部”按固定章节顺序展示，每章默认不超过 4 张。
4. “查看全部 / 收起”只影响对应章节，并保持当前滚动位置。
5. 点击分类后展示该类全部卡片；搜索可继续组合过滤。
6. 推荐严格为 6 张指定卡片。
7. 企查查·法律数据属于法律合规；企查查·文档报告属于效率工具并排在该章首位。
8. 设计创意至少显示 Seedream，卡片明确第三方服务商与计费提示。
9. 插件测试、lint、目录校验、npm 包检查和 Registry 测试/构建/校验全部通过。

## 七、发布边界

- UI、内置分类和 npm 包版本随插件仓库发布。
- 推荐标记调整与 Seedream 卡片由独立 Registry 发布；客户端刷新即可取得，无需等待下一次 npm 升级。
- Registry 探针不得执行本地 stdio 命令，目录文件不得携带 token、secret、API Key 或 password。
