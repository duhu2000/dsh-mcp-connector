# MCP连接器社区累计连接统计——企查查后端开发需求

版本：评审稿 v1.0 · 日期：2026-10-27 · 项目：dsh-mcp-connector · 客户端 PR： https://github.com/duhu2000/dsh-mcp-connector/pull/195

**状态：后端尚未开发。本文用于需求评审、排期与接口交付，不代表服务已上线。**

## 1. 目标与范围

在每张公开连接器卡片展示“累计成功连接”和“近30天新增”，支持累计热门、近期热门排序。数据来自主动参与统计的安装实例，帮助用户发现常用连接器，同时保留搜索相关性与人工精选。

首期交付：事件接收、严格校验、幂等去重、聚合查询、限流与异常监控、数据保留/删除方案、测试环境。首期不做账号画像、工具调用量、企业数据内容统计、收费或积分。下载量、点击量、工具注册数量不得混入成功连接数。

## 2. 指标定义（必须一致）

| 名称 | 定义 |
| --- | --- |
| 成功连接 | 客户端连接初始化、首次工具发现及配置保存全部成功；不是业务查询成功 |
| 累计成功连接 | 每个统计实例对每张公开卡片最多计1次，跨所有参与实例汇总 |
| 近30天新增 | 滚动30×24小时内发生的首次成功，排除已知历史卡片的验证成功 |
| 统计实例 | 独立随机 UUID；当前客户端按同一 DSH_HOME 共享，不是个人账号或独立用户 |
| 历史验证成功 | 参与前已有卡片配置，参与后真实验证成功；进入累计，不进入近期新增 |

重复连接、重新授权、升级、重启、同一卡片多个 Server 不重复增加；断开连接不扣减。一次 OAuth 授权涵盖多个资源，不能给尚未连接成功的卡片计数。参与前未上报的历史事件不补造。数据纠错、去刷及合法删除可使累计下降，应保留内部调整记录。

统计起点是正式服务启用时间，不能宣称产品问世以来全量累计。多设备、重建本机数据可能产生新实例；未参与用户不在覆盖范围。展示需明确“参与统计的实例，非独立用户”。

## 3. 前后端分工

客户端：默认关闭的参与开关；告知字段和政策；连接成功判定；随机实例/事件 ID；有限本地队列；重试；聚合展示和排序；退出后停止并清空未发送队列。

后端：可信公开卡片白名单；输入校验；事务去重；接收/聚合接口；限流与滥用识别；数据存储、保留和删除；监控告警；测试及生产环境。

不要求客户提供企查查业务 API Key，不复用 OAuth Token，不在开源插件中内置服务端共享密钥。若后端要求额外接入认证，需另行定义公开客户端可用的注册/短期凭据机制并评审，不能直接加一个固定秘密。

## 4. 接口一：接收成功连接事件

`POST {baseUrl}/v1/connection-events`，HTTPS，JSON，请求体最大4 KiB，拒绝未声明字段。客户端 Host 发送，非浏览器跨域调用；无需为任意网站开放 CORS。

```json
{
  "schemaVersion": 1,
  "eventId": "e51e632e-3435-4d85-a2df-bf144a8ec7c2",
  "instanceId": "7dff50f3-1225-4c27-b44b-ce97844cdb52",
  "connectorId": "公开目录稳定ID",
  "eventType": "first_success",
  "occurredAt": "2026-10-27T03:00:00.000Z",
  "pluginVersion": "0.2.83"
}
```

以上为测试示例，不写入生产数据。eventId/instanceId 为 UUID；connectorId 长度1～256且必须命中服务端公共目录；eventType 只允许 `first_success`、`baseline_success`；occurredAt 为 UTC ISO8601；pluginVersion 为版本字符串，最大80字符。版本示例不代表该功能已在0.2.83发布。

时间窗口提案：未来允许偏差5分钟，过去允许7天，与客户端重试期限匹配；后端需确认最终边界。不得接受客户端提交累计数量，不得把过期事件时间改成今日。

| HTTP | 响应／含义 | 客户端行为 |
| --- | --- | --- |
| 201 | `{"ok":true,"status":"accepted"}` 新事件完成事务提交 | 删除对应待发送事件 |
| 200 | `{"ok":true,"status":"duplicate"}` 已处理或同实例同卡片已计数 | 删除对应待发送事件 |
| 400 | 字段、格式或体积非法 | 终止此事件 |
| 403 | 拒绝接收 | 终止此事件，提示诊断 |
| 409 | 同eventId但payload不同 | 终止此事件并告警 |
| 422 | 非公开卡片或非法时间 | 终止此事件 |
| 429 | 限流，带 Retry-After（秒或HTTP日期） | 退避重试 |
| 5xx／超时 | 临时不可用 | 退避重试 |

失败体建议 `{"ok":false,"code":"invalid_event"}`，仅固定错误码，不回显原始数据。不得用 HTTP 200 + accepted 表示“已进入内存队列但可能丢失”；只有持久事务完成才能确认。

## 5. 幂等与数据模型

数据库选型由后端团队决定，以下为逻辑模型：

1. **事件幂等记录**：event_id唯一、规范化payload摘要、处理结果、received_at；同ID不同内容返回409。
2. **卡片首次成功事实**：唯一键 `(instance_id, connector_id)`，保存首个成功时间、事件类型、接收时间、来源事件ID。baseline_success不能被后来的first_success升格为新增。
3. **公共卡片目录**：稳定ID、是否允许接收、目录版本；命名变更或ID合并必须有迁移规则，不能制造新增。
4. **聚合快照**：每卡片累计、滚动30天新增、更新时间、统计起点；可从事实表重建。

事务：验证→登记幂等键→尝试插入首次成功事实→提交。重复唯一键返回duplicate，不能再次增加计数。聚合可异步计算，但必须有明确延迟。避免“先加累计，再写去重”导致失败重试重复加数。

事件记录清理与长期去重分开设计。删除幂等明细后仍需保留必要去重事实，否则再次连接会重复计数；保留多久、如何处理用户删除，必须在政策中明确。不能承诺永久准确同时删除全部去重键。

## 6. 接口二：公开聚合查询

`GET {baseUrl}/v1/connector-statistics`

```json
{
  "schemaVersion": 1,
  "scope": "participating-instances",
  "startedAt": "2026-10-27T00:00:00.000Z",
  "updatedAt": "2026-10-27T03:05:00.000Z",
  "items": [
    {"connectorId":"公开目录稳定ID","cumulativeSuccessfulConnections":123,"newSuccessfulConnections30d":12}
  ]
}
```

例子中的计数不是实际数据。计数为非负安全整数或null；新增不得大于累计；卡片ID不重复。null或缺失表示未知/隐藏，不得伪造为0。不得返回实例列表、账号或逐实例时间线。

提案：5分钟内更新聚合，支持Cache-Control，可选ETag。当前客户端JSON最多1 MiB、最多10,000项；缓存5分钟，超过24小时不展示；后端需确认容量。客户端当前未发送条件请求，不能无条件返回304。服务时间必须早于/等于当前时间允许偏差，startedAt不得晚于updatedAt。

## 7. 隐私与安全要求

允许字段仅为第4节清单。不收集Token/API Key、账号、邮箱、手机号、组织、设备序列号、私有URL、文件路径、对话、工具参数和结果。随机实例标识属于可关联标识，不声称完全匿名。

客户端开启前展示政策版本和说明；政策变化后必须重新同意。关闭后不生成新上传事件并清空队列；在途或已送达事件可能无法撤回，退出不等于删除服务端数据。

**后端上线前必须交付以下政策决策，不由客户端自行编造：**

- 事件明细、去重记录、网关/IP日志各自保存期限。
- 是否记录请求体（建议关闭）、日志脱敏与访问权限。
- 用户删除入口、实例归属证明、防止冒名删除、处理时限及删除后的聚合行为。
- 数据所在区域、运维负责人、隐私联系渠道、最终展示文案和policyVersion。

传输只用HTTPS；不重定向到任意域名；服务端限流、请求上限、白名单校验。实例UUID不是反作弊凭据，应组合速率限制、异常分布识别和人工审查；避免仅按IP限制导致企业出口用户全部被阻断。任何防刷规则不得给指定卡片人工补数。

## 8. 客户端队列与故障策略

现有实现：最多500个待发送事件，最长7天、最多10次发送；5秒请求超时；指数退避最大1小时；Retry-After最多1天；重试保留eventId和occurredAt。30秒检查一次，每轮至多一条；后续按容量评估批量化，不在v1隐式改变协议。

默认部署地址为空，不可开启生产统计。统计失败不得阻断业务连接。关闭和重新开启保留本机去重历史；队列满或过期丢弃不能借重连补造新的首次事件。后端须考虑漏报覆盖，不宣传绝对精确全量。

## 9. 监控与验收

后端监控：accepted/duplicate/invalid/rate-limited/error数量、写入延迟、队列/聚合滞后、数据新鲜度和异常增长；不使用业务内容做监控标签。提供健康检查和故障联系人。

| 用例 | 期望 |
| --- | --- |
| 同eventId并发100次 | 最多计1，其他duplicate |
| 不同eventId、同实例同卡片 | 累计仍1 |
| 同实例两卡片／两实例同卡片 | 分别计数 |
| 同eventId不同内容 | 409，不更改原事实 |
| 事务中断后客户端重试 | 不丢确认、不重复计数 |
| baseline_success后first_success | 累计1，近期新增0 |
| 30天窗口滑动 | 累计保持，新增加减符合时间窗口 |
| 失败连接／取消授权／未验证历史 | 客户端不发送，不计数 |
| 私有卡片、额外token字段、超限体积、过旧/未来时间 | 拒绝且日志不回显 |
| 超时、429、5xx、断网、重启 | 业务不受影响；重试保持事件ID |
| 关闭参与／政策版本变化 | 不继续上传；未发送队列按约定清理 |
| 聚合过期、null、计数矛盾 | 客户端隐藏或拒绝，不造0 |
| 删除、去刷、备份恢复 | 行为符合政策，调整可追溯 |

生产写入前先使用独立测试库和测试卡片，不把验收流量计入生产热度。

## 10. 交付与推进顺序

**后端负责人首次反馈：**确认负责人、技术方案、接口差异、时间窗口、预估排期，以及隐私政策的决策负责人。

**联调交付包：**测试baseUrl、最终OpenAPI/接口文档、政策文案与版本、白名单样例、测试数据清理办法、聚合刷新周期、错误响应样例和测试结果。

**生产交付包：**生产baseUrl、监控/告警/回滚步骤、数据备份与删除流程、最终政策、负责人验收结论。

推进：需求评审→后端开发/测试→客户端真实联调→问题修复与验收→客户端生产配置及文档截图→CI/PR合并→Tag/npm→安装验证与线上观察。未完成后端交付前保持PR草稿，不发布声称社区累计已上线的版本。
