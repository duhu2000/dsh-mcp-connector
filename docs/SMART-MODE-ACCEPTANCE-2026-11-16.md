## 5,000 的含义与证据

- 预算是 DSH 工具定义估算，采用非空工具数组 `Math.ceil(JSON.stringify(tools).length / 4) + 4`，空数组为 0；UTF-16 字符长度，不是 UTF-8 字节或模型 tokenizer。
- 智能组的两管理入口和已加载六服务定义共同受限于默认 5,000；策略可调低、不能超过 5,000。实际计数上限还受 `maxPrepared=32` 约束，不能声称可同时准备 47 项。
- TTL 默认 600,000 ms（10 分钟）滑动；固定 TTL 亦有契约。资源准入、LRU、批次/在途保护、定义增长、失败回滚由自动契约覆盖。
- 范围外工具、Host 内置工具、系统提示和历史消息不计入这个组内预算。兼容模式仍按原有注入行为，不受智能预算替代。

75 份 Host 证据共包含 113 个**离线适配器请求样本**，真实业务/真实模型请求均为 0。分布为：81 次两入口/421；7 次 3 条定义/478；2 次 3 条/483；2 次 3 条/485；21 次 5 条/505。定义条数含两个管理入口。

`scopedProjectedTokens` 是夹具从 Host 实际组装的 `request.tools` 调用本地估算函数得到的投影，不是 provider 返回 usage。两入口另算同为 421，说明序列化口径一致，不构成独立的真实计费校准。最大 505 来自小型合成定义，不能当作真实企查查查询实测。

## Windows tar 修订与回归

Git Bash 的 GNU tar 优先于 System32 时，裸 `tar.exe -xOf C:/...` 将盘符冒号解释为远程主机并报 `Cannot connect to C`。这是验收脚本 PATH 兼容性问题。修订后 Windows 从 SystemRoot/WINDIR 解析绝对 System32/tar.exe，缺失/相对系统目录时明确拒绝、不回退到 PATH；非 Windows 保留 tar。没有修改用户 PATH 或当前 DSH 配置。

没有统一添加 `--force-local`：本机原生 bsdtar 明确不支持该参数。永久回归覆盖环境变量大小写、WINDIR 回退、异常系统目录、非 Windows，以及真实 tgz 的空格路径/Windows 盘符；将会拒绝 tar 参数的 Node 可执行文件置于临时 PATH 前端，证明仍能用原生 tar 正确解包。

CI 在 Windows 增加 Git Bash 完整生命周期，把 /usr/bin 放在本进程 PATH 前端，保留 GNU tar 版本证据，确保同一修订在普通 PowerShell 与 GNU tar 优先环境均受门禁。
